# Product FAQ Localization Inventory — Phase 7

Audit-only inventory of Phase 6 finding F2, produced before any file was modified.

## 1. English source FAQ strings

The product FAQ block is generated for the English root pages by
`scripts/remediate_production_claims.py`'s `product_faq()` function, which reads
`data/products.json` directly (not hand-authored per page). It renders exactly 5
question/answer pairs per product:

| Key | Question template | Answer template |
|---|---|---|
| `product_faq.spec` | What specification is published for {name}? | The current reference specification lists {spec_text}. These are planning values; the signed specification, approved sample and agreed tolerances control the order. |
| `product_faq.hs_moq_packing` | What are the HS code, MOQ and packing options for {name}? | Reference HS code: {hs_code}. MOQ: {moq}. Published packing: {packaging}. Classification, packing and legal weight limits must be confirmed for the destination and contract. |
| `product_faq.container` | How much {name} fits in a container? | The planning reference for a 20-foot container is {container_20ft}. Final payload depends on bag construction, palletisation, carrier limits, route and applicable law; the written loading plan controls. |
| `product_faq.documents` | Which documents can be requested for {name}? | The base document set is {documents}. {conditional} are arranged only when applicable and written into the quotation or contract. |
| `product_faq.sample` | Can I request a trade sample of {name}? | Qualified trade buyers may request a standard 250–500g evaluation sample per selected product. Availability, final size, courier cost and dispatch timing are confirmed before shipment; larger samples require separate written approval. |

`{name}`, `{spec_text}`, `{hs_code}`, `{moq}`, `{packaging}`, `{container_20ft}`,
`{documents}`, `{conditional}` are substituted per-product from `data/products.json`
fields `t`, `s`, `trade.hs_code`, `trade.moq`, `trade.packaging`,
`trade.container_20ft`, `compliance.documents`, `compliance.conditional_documents`.

## 2. Where the strings originate

`remediate_production_claims.py` (a prior-phase content-remediation script,
already present in the repo) rewrote the English root pages' FAQ content to this
data-driven, 5-question design at some point before Phase 6. Its `main()`
applies `product_faq()` **only to `root_path = ROOT / product["u"]`** (the
English root page) — the same script's locale loop
(`for locale in ("en",) + LOCALES: localize_product_page(...)`) applies a
completely different set of regex substitutions (carrier claims, company-history
claims, sample wording) and never touches the FAQ section on locale pages at
all. This is the exact point where the pipeline forked.

## 3. Where localized FAQ output originated (pre-Phase-7)

Locale FAQ content was never regenerated by any script still present in the
repository. It reflects an **earlier, since-retired English FAQ design** — a
different 5-question set (MOQ, payment terms, certificates, shipping time,
sample request) that predates the current design and was, at the time,
partially translated: most of each answer is genuinely translated, but one
leading English clause per question survived untranslated in 2 of the 5 old
questions, and 1 of the 5 old questions (the sample-request one) was never
translated at all. Confirmed no current script or generator produces this old
content — it exists only as static, previously-committed HTML.

## 4. Why the old translation did not propagate

There is no regeneration step for product-page body content analogous to
`build_locale_ui.py`/`audit_locale_ui.py` for header/footer text (Phase 2). Once
`remediate_production_claims.py` rewrote the English FAQ, nothing re-ran a
locale-aware equivalent, and nothing detected that locale pages had fallen out
of sync — this is the same systemic gap already named as F2's root cause in
`reports/localization-quality-2026-08-27.md`.

## 5. Where the FAQ content is stored

| Candidate location | Verdict |
|---|---|
| `data/products.json` | Holds the **variables** (spec values, HS code, MOQ, packaging, documents) but not the question/answer sentence templates. |
| HTML (English root) | Not the source — it's the *rendered output* of `product_faq()`, regenerated from `data/products.json` each time that script runs. |
| `data/localized-copy-cache.json` | Holds **reusable vocabulary** (product names, spec labels, document-type names) referenced by the new templates, but never held the FAQ sentence templates themselves before this phase. |
| Generated locale files | The *retired* FAQ content lived only here — static, uncommitted-to-any-generator HTML. |
| Templates | No template file existed for this content before this phase. |
| Scripts | `remediate_production_claims.py` contains the *English* template as Python string literals — locale equivalents did not exist. |
| **New in Phase 7**: `data/product-faq-templates.json` | **This is now the governed source** for the question/answer sentence templates, one entry per key x locale, each carrying a `status` (all `draft_pending_native_review`, consistent with the site's pre-existing `localization-review.json` policy). |

## 7. Universal vs. product-specific (Part B)

**Hybrid.** The 5 question/answer **templates** are universal (identical
sentence structure for every product, in every locale). The **variables**
embedded in them are strictly product-specific and are substituted from
`data/products.json` at generation time, never flattened or generalized:

- `{name}` — the product's own governed, already-translated commercial name
- `{spec_text}` — up to 5 of the product's own spec label:value pairs (labels translated, numeric/unit values preserved verbatim)
- `{hs_code}`, `{moq}`, `{packaging}`, `{container_20ft}` — preserved verbatim (codes, quantities, units)
- `{documents}`, `{conditional}` — the product's own document-requirement lists (translated document-type names, but the list membership itself is product-invariant since all 84 products share the same 2 document tuples — confirmed by direct inspection, not assumed)
